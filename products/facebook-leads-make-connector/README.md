# LeadBridge for Make — reliable Facebook Lead Ads → Make.com

**Not part of the Opportunity Engine.** This is the first product built *from* an
opportunity the engine surfaced (see `docs/root_cause_notes.md` for the two real
community.make.com threads this is grounded in). It lives in this repo only as a
convenient monorepo location — different dependencies, different tests, different
`pyproject.toml`, no shared code with `src/opportunity_engine`.

## The problem (verified against two real, current community.make.com threads)

1. **Multi-form field mapping breaks.** Make's native "Facebook Lead Ads" module
   maps fields statically per scenario. A Page with several Instant Forms — each
   with different custom questions — needs either N duplicate scenarios or a
   single scenario that silently drops fields it wasn't mapped for. One thread's
   own suggested workaround was routing everything through a Google Sheet first —
   a workaround, not a fix.
2. **Lead retrieval fails outright for some users**, even with every documented
   permission granted: `GraphMethodException` code 100, "Object with ID X does
   not exist," on the `GET /{leadgen_id}` call itself. Root cause is almost
   certainly a token-scope mismatch (`leads_retrieval` permission specifically,
   or a Page token generated by someone without an advertiser role on the ad
   account) that Facebook's own error message doesn't surface clearly, and
   Make's UI doesn't validate before you're already stuck.

## What this ships

- `src/leadbridge/` — a small FastAPI webhook service that sits between Facebook
  and Make: receives the raw `leadgen` webhook, retrieves the lead from the Graph
  API with pinned API version + retry + upfront token-scope validation (fixes
  problem 2), normalizes arbitrary per-form field names into one predictable
  schema (fixes problem 1), dedupes, and forwards one clean JSON payload to a
  single Make custom-webhook trigger.
- `docs/SETUP.md` — Facebook App/Page/token setup, deploy, Make scenario wiring.
- `docs/make_blueprint_spec.md` — exact module-by-module spec for the one
  downstream Make scenario (Custom Webhook → Router → Airtable/Outlook/Gmail).
- `landing/index.html` — draft sales page copy, unpublished.

## What is NOT done, and needs a real account to finish

See `docs/SETUP.md`'s final checklist. In short: a real Facebook App + Page +
long-lived Page Access Token, a hosting deploy (Render/Fly/Docker anywhere),
a Make.com account to build the one downstream scenario, and — only once you
decide to sell it — a Stripe account and Payment Link (see `docs/SETUP.md`
§6, including the VAT/merchant-of-record caveat before going live). None of
these were created on your behalf; none require code changes to set up.

## Running it locally

```
cd products/facebook-leads-make-connector
python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"
cp .env.example .env   # fill in FB_APP_SECRET, FB_PAGE_ACCESS_TOKEN, FB_WEBHOOK_VERIFY_TOKEN, MAKE_WEBHOOK_URL
.venv/bin/pytest -q
.venv/bin/uvicorn leadbridge.main:app --reload
```
